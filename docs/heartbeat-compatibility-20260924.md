# 心跳、重连和兼容性复查（2026-09-24）

本轮在已有 1.1.4 心跳优化上继续修复；协议号仍为 5，注册 TLV、心跳 uptime、终端、文件、HTTP 消息格式均未改变。
检查 `v1.1.1` 至当前 `proto/proto.go`，变化仅为写入互斥锁。

## 客户端本轮变化

- 每次重连创建独立的 `RttyClient`，旧命令、HTTP、终端和计时器只持有旧连接，不能写入或关闭下一条连接。
- 连接写入串行设置 10 秒截止时间，写失败关连接并解阻塞接收。
- 心跳等待窗口为 `max(2 × 间隔, 10 秒)`；默认间隔仍为 30 秒，给第二次探测留出机会。
  注册后约 30 秒、60 秒发送探测，持续没有消费服务器消息时约 90 秒断开。
  写超时等其他错误可能更早触发断开。
- 心跳超时日志补充最近收发间隔和正在处理的消息类型，避免把本地消费阻塞一律当成网络故障。
- Stop 可取消拨号、打断重连等待；Close 幂等，关闭后不能重新创建心跳或终端计时器。
- 终端 ACK/Close/Wait 使用同一条件锁，关闭会释放所有等待者，发送失败后不再进入 ACK 等待。
- 命令用户/路径查找移至原有限流后台任务。命令执行仍使用原有 30 秒超时，不因一次断网新增立即终止命令的行为。
- HTTP 旧对象清理不会删除同地址的新对象。

代价：对于完全无响应但写入未报错的连接，重连检测会比旧版本更晚。
重连等待仍为原有随机 5～14 秒；Token、TLS、配置文件字段没有变化。

## 互通结果

以 `1cf149f`（1.1.3）和本轮 1.1.4 分别编译 Windows 客户端，连接旧 gwmgr (`83b575b`) 与本轮服务端：

| 客户端 | 旧服务端 | 本轮服务端 |
| --- | --- | --- |
| 1.1.3 | 注册、两次空闲心跳、HTTP 代理通过 | 同左 |
| 本轮 1.1.4 | 注册、两次空闲心跳、HTTP 代理通过 | 同左 |

近期改动没有要求新旧两端同时升级。但旧服务端仍有同步转发阻塞和注册回复顺序竞态，
旧客户端仍可能采用 3 秒心跳回复等待，混用不会自动获得对端的软件修复。
先更新服务端，再灰度更新客户端更便于验证。

**同组同 ID 不能同时运行新旧两个进程。** gwmgr 会让新连接接管旧连接；双方都自动重连时会循环互踢，空闲时也能发生。
升级前后需要确认守护进程与手动启动实例没有并存。

## 验证边界

`go test ./...`、`go vet ./...` 通过，连接生命周期等新增回归连续 3 轮通过，Linux ARM64 交叉编译通过。
注册帧有逐字节回归；gwmgr 另有协议 3/4/5 接收兼容性测试。
Windows 互通测试未覆盖真实 Linux PTY/PAM 和文件传输；本机 CGO 未启用，尚未运行 race 检测。

终端输入和文件操作仍有同步 PTY/磁盘/FIFO 处理路径。若日志出现 `handling=termdata/file/login`，
需在 Linux 上继续定位对应处理阻塞，不能据此认定网络或协议不兼容。
已有 `rtty-1.1.2/1.1.3/1.1.4-linux-arm64` 目录内的发布文件未替换；本轮未提交或部署。
